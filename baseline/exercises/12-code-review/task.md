# 12｜程式碼審查

- 難度：★★★☆☆
- 沒有測試

## 情境

假設這個專案下週就要接上正式環境，你是負責審查的資深工程師。請在修完前面 11 題之後，以修正後的版本為準，寫一份程式碼審查意見。

## 要求

- 至少列出 **8 個**改進點。每一點寫出：
  1. 位置（類別或方法）
  2. 問題是什麼、在什麼情況下會出事
  3. 建議怎麼改，以及代價或取捨
- 依嚴重程度排序：正確性與資料一致性 → 並發與鎖 → 營運與可觀測性 → 效能 → 可維護性。
- 不要重複前 11 題的 bug。可以延伸它們，例如「修好之後，同一類問題還可能出現在哪裡」。

## 提示方向（不必全部涵蓋）

交易邊界、冪等性、並發寫入、鎖的生命週期、批次重跑與重啟、schema 管理、金額與日期的處理、錯誤處理與對外訊息、API 設計、測試策略。
